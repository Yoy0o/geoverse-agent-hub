# 少读、少关联的工作台：首个实施切片

目标：打开“今日”即可知道发生了什么、影响哪些已有工作、现在需要决定什么。

本轮沿用现有任务作为工作单元。独立工作主题、成果库和自动调度放到后续切片，避免同时改动数据结构、执行链路和部署方式。

## 本轮修改

1. 工作摘要：当前结论、下一步、待决策问题、推荐动作、风险、证据链接。
2. 增量阅读：比较当前业务状态与上次明确标记已读的快照；忽略心跳、耗时和更新时间等过程噪声。
3. 关联已有工作：按任务 ID 记录复用、补充、替代、影响，展示关联任务当前状态。缺失的关联明确提示。
4. 今日决策卡：默认优先显示三项需要处理的工作；阻塞、失联、验证失败和风险事项不受此数量限制。一般变化、统计、日志按需展开。
5. 接入：REST 与 MCP 复用同一领域服务，Agent 可读上下文、提交简短摘要；页面负责已读与采纳操作。

## 行为边界

- 读取、标记已读、采纳建议、任务评审是不同动作。前两者不代表认可成果，采纳建议不触发执行、合并或改任务状态。
- 每个写入携带正在查看的业务快照指纹。页面或 Agent 使用过期上下文时返回 409，要求刷新后处理。
- 业务快照指纹只标识 Hub 中的工作状态，不等于源码 commit。验证代码成果仍需提供具体 commit 或证据版本。
- 摘要不会因为新的回执到达而自动消失；新的回执、检查与关联任务状态会单独进入变化列表。过期决策需要重新确认。
- 默认自动归纳只使用已有结构化字段；不添加后台 LLM 调用。Agent 通过新工具维护短摘要。系统不会凭语义相似自动关联任务。
- 新字段保存于任务中，原任务 ID、回执、执行管理、备份、同步保持兼容。个人 Hub 共用一个已读进度；未来多用户需要单独的阅读状态。
- 旧回执的长摘要默认显示最多 280 字，原文保留在依据中。长风险和未知验证不从依据中删除；首屏显示风险预览，完整内容可展开。

## 接口

| 接口 | 用途 |
|---|---|
| `GET /api/focus` | 获取优先处理项与普通变化 |
| `GET /api/tasks/:id/focus` | 获取业务快照、指纹、相对已读版本的变化 |
| `GET /api/tasks/:id/focus/context` | 获取可复制给下一个 Agent 的当前上下文 |
| `PUT /api/tasks/:id/focus` | 提交摘要、证据、关联；必须携带 `expectedFingerprint` |
| `POST /api/tasks/:id/focus/read` | 标记当前所见快照已读，不能代替验收 |
| `POST /api/tasks/:id/focus/decision` | 记录采纳或要求调整的决定，不能触发任务执行 |
| MCP `get_focus` | 为“今天需要我判断什么”提供精简入口 |
| MCP `get_work_context` | 获取任务的当前结论、变化、关联和完整任务单 |
| MCP `update_work_brief` | 以短字段更新工作摘要 |

字段与长度以 `src/focus.js` 的 Schema 为准。关系必须指向确实存在的其他任务；证据使用 HTTP(S) 链接并可标注版本。接口校验内容与并发，沿用 Hub 的现有鉴权。

## 验收

- 连续两次更新后，变化仍相对于上次已读版本，不能只显示最后一次更新。
- 重复读取和心跳不会清除未读；标记已读不会清除未决问题。
- 采纳建议后任务仍维持原状态；新回执、风险或关联工作变化会使旧决定过期。
- 更新与标记已读都拒绝过期指纹，避免多设备漏读或覆盖。
- 旧任务无需迁移即可展示；删除关联任务后显示“已不存在”。
- 输出转义；证据链接禁止脚本协议；移动端可用，展开状态与输入内容不因定时刷新丢失。
- 运行领域与 REST/MCP 集成测试、现有 CI 检查、Cloudflare 构建及运行验证。
