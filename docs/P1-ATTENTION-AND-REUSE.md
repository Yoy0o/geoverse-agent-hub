# P1：少打扰与成果复用（0.6.0）

这一批解决两件事：已有待办反复占据注意力，以及想复用成果时还要重读历史对话。打开“今日”处理当前需要判断的事项；需要找旧成果时切到“成果”。

## 日常只做这几步

1. **看今日卡片**：先处理阻塞、失败、风险和失联事项。它们始终显示，不能暂缓隐藏。
2. **安排普通事项**：暂时不准备评审的普通任务，展开“稍后处理”，选 1 小时或 24 小时。它会移到折叠区，到期或工作内容变化时重新出现，也可随时恢复显示。执行中的 Agent 会继续运行；需要真正切换执行时使用[暂停与恢复](P1-PAUSE-RESUME.md)。
3. **清理普通变化**：展开普通变化，阅读后可一次标记最多 50 项已读。只处理按钮对应的版本；期间有变化、变成待决策或被删除的任务会跳过并反馈数量。该操作不会验收任务。
4. **查找已有成果**：在“成果”输入关键词，可同时筛选项目。默认只显示当前已验收版本；切到“全部当前版本”或“全部版本”查看未验收、历史和归档成果。每页 20 条，结论最多 280 字；点击“打开此版证据”查看完整依据。
5. **引用具体版本**：点击“引用到任务”，选已有目标任务，说明复用内容及适用限制。确认后保存来源任务、固定成果编号与说明，目标任务仍按自己的要求验证和验收。“复用摘要”可用于复制到新的 Claude / Codex 会话，本身不写入关联。

搜索按关键词匹配任务名称、编号、项目、回执结论、版本、声明的文件路径、交付时的目标与验收条件及验证命令；多个词需同时匹配。不进行语义搜索、不调用模型、不自动判断两个任务应该关联。

## 常规示例：从单层导航扩展到新仓库

已完成任务保留“主次通道衔接与断连用例已验证”的成果。新仓库任务开工前，搜索“导航 断连”，打开命中的具体版本核对。

选择“引用到任务 → 新仓库室内导航”，说明：“复用单层通道连接实验；新仓库障碍物和跨楼层仍需独立验证。”之后读取新任务的工作上下文即可看到固定版本、结论和复用限制，不必粘贴整段旧对话。

来源后来交付新版时，引用仍停留在原版，目标任务会出现关联变化。需要换版时再次明确选择；同一来源任务只有一条关联，重新引用会替换其版本与说明。来源被删除或恢复备份后缺失，显示缺失提示，不自动转向其他成果。

## 临时插单示例：Safari 视频黑屏

导航任务仍在执行时，先保存断点并暂停执行，再处理独立的视频故障任务。当天另有一项无需立即决定的常规评审，可暂缓 1 小时，减少今日卡片数量。

视频任务发生新失败或风险时始终进入今日队列；暂缓期间有新回执、相关检查变化、需求变更或关联变化，也会重新出现。处理完视频任务，从原断点恢复导航工作。**“稍后处理”管理注意力，“暂停”管理执行，两者独立。**

## Agent 与接口

| 目的 | MCP | REST |
| --- | --- | --- |
| 查看今日与暂缓项 | `get_focus` | `GET /api/focus` |
| 暂缓或恢复显示 | `defer_task_attention` | `POST /api/tasks/:id/focus/defer` |
| 批量标记普通变化已读 | 由网页明确操作 | `POST /api/focus/read` |
| 检索成果 | `search_deliveries` | `GET /api/deliveries?q=导航&scope=accepted&limit=20&offset=0` |
| 核对某版成果 | `get_delivery(id, revision)` | `GET /api/tasks/:id/delivery/:revision` |
| 保存固定版本引用 | `reuse_delivery` | `POST /api/tasks/:id/reuse` |

暂缓请求为 `{expectedFingerprint, minutes}`：先读目标任务的工作上下文指纹，分钟数为 1–10080，0 表示取消。网页提供 1 小时和 24 小时；使用经过时长，避免设备时区差异。只有用户明确要求时 Agent 才可暂缓，不能为了让今日列表好看而自动隐藏任务。

引用请求示意，提交前替换占位内容：

```json
{
  "expectedFingerprint": "目标 get_work_context 的当前指纹",
  "sourceTaskId": "来源任务编号",
  "deliveryId": "明确选择的成果编号",
  "expectedSourceFingerprint": "来源 get_delivery 的当前验收指纹",
  "note": "复用单层连接实验；新场景仍需验证"
}
```

两个指纹用途不同。409 表示来源或目标已变化；先重新核对，再提交。网页保留复用说明，提供“重新读取并核对”。引用历史或未验收版本时会明确提示其状态；缺少实际版本的旧回执不能通过引用入口绑定。更新摘要时应保留 `relations[].deliveryId`，不要把固定版本引用无意改成仅关联任务。

## 保存和边界

- 暂缓、阅读进度和版本引用都随任务备份与同步保存。取消暂缓留有记录，避免另一端的旧设置把任务重新隐藏。内容指纹不包含心跳、成本或暂缓设置，无变化的过程消息不会重新制造未读。
- 今日是 Hub 内的队列，不是系统推送或定时消息。打开页面时按当前时间判断到期，页面通常每 30 秒刷新；不会启动后台 Agent。
- 个人 Hub 共用阅读和暂缓状态。没有新增多人独立提醒、全文索引服务或自动成果推荐；搜索读取现有任务数据，大规模数据的索引优化留待实际规模需要。
- “当前已验收”严格采用当前版本的验收判断；历史曾获批准不等于当前仍有效。引用只记录依据，不复制交付、验收标准勾选、批准或任务状态。
- 这是代码版本改进，部署与线上核验仍按[发布指导](P0-RELEASE-AND-NEXT-STEPS.md)单独处理。上线后更新接入包以获取新的 Agent 使用约定。

下一步宜先用一周真实任务观察：每日需人工处理的卡片数、查找并引用旧成果所需时间、暂缓后重新出现的原因。再决定示例数据隔离与历史数据清理范围，避免通过隐藏有效风险来获得更少的卡片。
